1 概述
1.1 文档目的与范围
本文档是禾伴 App 编码前的技术准备，后续代码按本文档实现。界面和交互以《禾伴 UI 设计文档 v2.0》和原型图（64 页）为准，本文档说明用什么框架、怎么组织代码、数据怎么存、接口怎么调。
本期范围：只开发 App 端。暂时没有自己的后端，账号、作物、社交等数据保存在手机本地并用模拟数据填充；以下几项直接接入真实的第三方服务：
•  AI 问答：DeepSeek（流式输出）；
•  拍照识别：把图片发给支持识图的大模型，主模型 DeepSeek 视觉模型，备用通义千问 VL；
•  天气：和风天气；
•  短信验证码：阿里云号码认证服务的「短信认证」。
代码分层时预留后端接口，后端完成后只替换数据层实现，页面和 ViewModel 不改（见第 5 章）。

2.3 local.properties 配置
local.properties 已在 .gitignore 中，每位开发者在自己电脑上填写。没有填写的项会让对应功能自动退回模拟模式（例如短信没有配置 AccessKey 时使用固定验证码 123456）。
local.properties（示例，值替换为自己的）

2.4 包名迁移步骤
现有工程的包名是 com.example.androidtest1，开工第一步改为 com.heban.app：
1.  app/build.gradle 中 namespace 和 applicationId 改为 com.heban.app；
2.  在 Android Studio 中对 java/com/example/androidtest1 包执行 Refactor → Rename，改为 com/heban/app（测试目录同样处理）；
3.  AndroidManifest.xml 中的类名引用随重构自动更新，检查 application 的 android:name 和 activity 名称；
4.  settings.gradle 中 rootProject.name 可改为 "HeBan"（可选）；
5.  Sync 后运行一次，确认能正常启动，再开始后续开发。

•  日常开发使用 mockDebug；后端联调使用 remoteDebug。
•  release 暂不开启混淆（minifyEnabled false）。如果以后开启，需要在 proguard-rules.pro 中保留 Gson 解析用的 DTO 和 Room 实体字段，并加入 Retrofit、OkHttp、Glide 官方提供的混淆规则。

5 总体架构
5.1 分层结构
采用 MVVM。View 层只负责显示和转发用户操作；ViewModel 持有页面状态；Repository 接口屏蔽数据来源。数据从数据库或网络以 RxJava 数据流的形式返回，ViewModel 把它转成 LiveData，再由 DataBinding 显示到界面上。
图 5-1 总体架构
表 5-1 各层职责
层 | 职责 | 不应该做的事
View（Fragment + XML） | 绑定 ViewModel、观察 LiveData、处理导航和权限申请、显示 Snackbar / 对话框 | 直接访问数据库或网络；保存业务状态
ViewModel | 持有 LiveData 状态；调用 Repository；组合多个数据流；处理表单校验 | 持有 View / Context 引用（需要时用 Application）
Repository | 决定数据从哪里来（Room、网络、缓存）；线程切换（subscribeOn io）；错误转换 | 引用任何界面类
数据源 | DAO、DataStore、Retrofit 接口、LlmClient、SmsService | 包含业务判断

5.4 页面状态与错误处理
每个列表或详情页面都用 UiState 表示「加载中 / 成功 / 空 / 错误」四种状态，对应 UI 设计文档第 7 章的页面状态设计。所有异常在 Repository 或 ViewModel 中转换为 AppError，界面只显示 AppError 中的中文提示。
ui/common/UiState.java
public final class UiState<T> {    public enum Status { LOADING, SUCCESS, EMPTY, ERROR }     public final Status status;    @Nullable public final T data;    @Nullable public final AppError error;     private UiState(Status s, @Nullable T d, @Nullable AppError e) {        status = s; data = d; error = e;    }     public static <T> UiState<T> loading() { return new UiState<>(Status.LOADING, null, null); }    public static <T> UiState<T> success(T d) { return new UiState<>(Status.SUCCESS, d, null); }    public static <T> UiState<T> empty() { return new UiState<>(Status.EMPTY, null, null); }    public static <T> UiState<T> error(Throwable t) {        return new UiState<>(Status.ERROR, null, AppError.from(t));    }     public boolean isLoading() { return status == Status.LOADING; }    public boolean isEmpty() { return status == Status.EMPTY; }    public boolean isError() { return status == Status.ERROR; }}
表 5-3 AppError 类型
类型 | 来源 | 提示文案
NETWORK | UnknownHostException、ConnectException 等 IOException | 网络不太好，检查后再试一次
TIMEOUT | SocketTimeoutException、RxJava timeout | 请求超时，请稍后重试
UNAUTHORIZED | HTTP 401 | API Key 无效，请到「AI 助手设置 → 模型服务」检查
NO_BALANCE | HTTP 402（DeepSeek 余额不足） | 模型服务余额不足
RATE_LIMIT | HTTP 429；短信频率限制 | 操作太频繁，请稍后再试
SERVER | HTTP 5xx | 服务暂时不可用，请稍后重试
PARSE | JsonParseException、识图结果格式错误 | 返回内容无法识别
BUSINESS | 短信 Code 不为 OK、验证码错误、账号已存在等 | 直接显示业务提示
UNKNOWN | 其他 | 出了点问题，请重试
5.5 线程与生命周期规范
1.  Repository 返回的数据流在 Repository 内部指定 subscribeOn(Schedulers.io())；ViewModel 订阅时用 observeOn(AndroidSchedulers.mainThread())。
2.  所有订阅放入 BaseViewModel 的 CompositeDisposable，onCleared() 时统一 clear，避免内存泄漏和页面关闭后回调。
3.  Room 的 Flowable 查询会在数据变化时自动重新发射，界面数据以数据库为准（单一数据源）。
4.  ViewModel 用 LiveDataReactiveStreams 把 Flowable 转成 LiveData 时，要注意它在没有观察者时会取消订阅；需要一直保持的流（如流式回答）改为手动订阅并写入 MutableLiveData。
5.  HeBanApp 中设置 RxJavaPlugins.setErrorHandler，记录 UndeliverableException，防止页面关闭后迟到的错误导致崩溃。

7.4 敏感信息加密
用户在 App 中填写的 API Key、模拟登录 Token 等敏感信息，用 Android Keystore 中的 AES-256-GCM 密钥加密后再存入 DataStore。密钥由系统保管，不能被导出。
data/local/prefs/SecureStore.java
public final class SecureStore {    private static final String ALIAS = "heban_secret_key";    private static final String TRANSFORM = "AES/GCM/NoPadding";     private SecretKey key() throws GeneralSecurityException, IOException {        KeyStore ks = KeyStore.getInstance("AndroidKeyStore");        ks.load(null);        if (ks.containsAlias(ALIAS)) {            return ((KeyStore.SecretKeyEntry) ks.getEntry(ALIAS, null)).getSecretKey();        }        KeyGenerator kg = KeyGenerator.getInstance(                KeyProperties.KEY_ALGORITHM_AES, "AndroidKeyStore");        kg.init(new KeyGenParameterSpec.Builder(ALIAS,                KeyProperties.PURPOSE_ENCRYPT | KeyProperties.PURPOSE_DECRYPT)                .setBlockModes(KeyProperties.BLOCK_MODE_GCM)                .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)                .setKeySize(256)                .build());        return kg.generateKey();    }     public String encrypt(String plain) throws GeneralSecurityException, IOException {        Cipher cipher = Cipher.getInstance(TRANSFORM);        cipher.init(Cipher.ENCRYPT_MODE, key());        byte[] iv = cipher.getIV();                                   // 12 字节        byte[] body = cipher.doFinal(plain.getBytes(StandardCharsets.UTF_8));        byte[] out = ByteBuffer.allocate(iv.length + body.length).put(iv).put(body).array();        return Base64.encodeToString(out, Base64.NO_WRAP);    }     public String decrypt(String encoded) throws GeneralSecurityException, IOException {        byte[] all = Base64.decode(encoded, Base64.NO_WRAP);        Cipher cipher = Cipher.getInstance(TRANSFORM);        cipher.init(Cipher.DECRYPT_MODE, key(), new GCMParameterSpec(128, all, 0, 12));        return new String(cipher.doFinal(all, 12, all.length - 12), StandardCharsets.UTF_8);    }}
模拟账号的密码不加密保存，而是用 PBKDF2WithHmacSHA256（随机 16 字节盐、10000 次迭代）计算哈希后保存，登录时比对哈希。

8.3 阿里云短信认证
个人实名的阿里云账号无法申请普通「短信服务」的签名，因此使用号码认证服务中的「短信认证」：调用 SendSmsVerifyCode 发送验证码、CheckSmsVerifyCode 校验，验证码由阿里云生成和校验，使用控制台赠送的签名和模板，不需要企业资质。
安全　现阶段由 App 直接调用接口，AccessKey 会打包进 APK。务必使用只授权这两个接口的 RAM 子账号，在控制台设置发送频率和每日上限，APK 不对外分发；后端上线后改为由服务端调用（App 只请求后端的发送 / 校验接口）。

public final class AliyunSigner {    private static final String ENDPOINT = "https://dypnsapi.aliyuncs.com/";     /** 返回已签名的完整 GET 地址 */    public static String signedUrl(String action, Map<String, String> bizParams,                                   String akId, String akSecret) throws Exception {        TreeMap<String, String> p = new TreeMap<>(bizParams);   // 参数按名称排序        p.put("Action", action);        p.put("Version", "2017-05-25");        p.put("Format", "JSON");        p.put("AccessKeyId", akId);        p.put("SignatureMethod", "HMAC-SHA1");        p.put("SignatureVersion", "1.0");        p.put("SignatureNonce", UUID.randomUUID().toString());        SimpleDateFormat f = new SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss'Z'", Locale.US);        f.setTimeZone(TimeZone.getTimeZone("UTC"));        p.put("Timestamp", f.format(new Date()));         StringBuilder query = new StringBuilder();        for (Map.Entry<String, String> e : p.entrySet()) {            if (query.length() > 0) query.append('&');            query.append(enc(e.getKey())).append('=').append(enc(e.getValue()));        }        String stringToSign = "GET&" + enc("/") + "&" + enc(query.toString());        Mac mac = Mac.getInstance("HmacSHA1");        byte[] key = (akSecret + "&").getBytes(StandardCharsets.UTF_8);        mac.init(new SecretKeySpec(key, "HmacSHA1"));        String signature = Base64.encodeToString(                mac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)), Base64.NO_WRAP);        return ENDPOINT + "?" + query + "&Signature=" + enc(signature);    }     /** 阿里云要求的编码：空格 %20、* 为 %2A、~ 不编码 */    static String enc(String s) throws UnsupportedEncodingException {        return URLEncoder.encode(s, "UTF-8")                .replace("+", "%20").replace("*", "%2A").replace("%7E", "~");    }}

public final class RoundedCornersTransformation implements Transformation {    private final float radius;     public RoundedCornersTransformation(float radiusPx) { this.radius = radiusPx; }     @Override    public Bitmap transform(Bitmap source) {        int w = source.getWidth(), h = source.getHeight();        Bitmap out = Bitmap.createBitmap(w, h, Bitmap.Config.ARGB_8888);        Paint paint = new Paint(Paint.ANTI_ALIAS_FLAG);        paint.setShader(new BitmapShader(source, Shader.TileMode.CLAMP, Shader.TileMode.CLAMP));        new Canvas(out).drawRoundRect(new RectF(0, 0, w, h), radius, radius, paint);        if (out != source) source.recycle();             // Picasso 要求：返回新图时回收原图        return out;    }     @Override    public String key() { return "rounded-" + radius; }   // 参与缓存键}

12.1 账号（A01–A09）
•  起始页：MainActivity 读取 onboarding.done 和 session.user_id，决定进入 A02 引导页、A03 登录还是 H01 首页；判断完成前保持系统闪屏（A01）。
•  A02 引导页：同一个 Fragment 内切换 3 屏内容（状态存在 Fragment 中），最后一屏「开始使用」进入 A05 注册，「跳过 / 已有账号」进入 A03。
•  A03 密码登录：PBKDF2 比对密码哈希；连续输错 5 次锁定 10 分钟（本地计数）；未勾选协议时点击登录弹出 Snackbar「请先阅读并勾选同意协议」。
•  A04 验证码登录：SmsService.verify 通过后，手机号未注册则自动创建账号（默认昵称「农友 + 手机号后四位」）并进入首页。
•  A05 / A06 注册：两步共享 RegisterViewModel；密码规则 8–20 位、同时包含字母和数字，PasswordStrength 实时计算强度；A06 可跳过。
•  游客浏览：session.guest = true；点赞、评论、发布、私信、签到等操作先调用 requireLogin()，未登录时弹出对话框引导登录。
•  A07 / A08 找回密码：手动输入手机号并校验验证码 → 设置新密码 → 更新哈希、清除登录态 → 显示「密码已重置」→ 返回 A03。
•  A09 申诉换绑：三步（原手机号信息 → 新手机号验证码 → 已提交），保存 appeal 记录，状态显示「人工审核中」；后端上线后由后端审核并短信通知。
•  退出登录只清除登录态，保留本机作物数据；注销账号需勾选「我已了解以上后果」，本地标记 deleted_at，7 天内重新登录可撤销。
12.2 首页（H01–H05）
•  H01：Flowable.combineLatest 合并天气、今日农事、我的作物、未读消息数四个数据流生成 HomeState；问候语按时间段变化；勾选完成农事时写入 done，并按规则奖励积分（完成今日农事 +5，每天 1 次）。
•  H02：Single.zip 并发请求三个天气接口；FarmIndexCalculator 计算农事指数；点击定位图标通过城市搜索切换地点。
•  H03：月历用 RecyclerView + GridLayoutManager（7 列）自绘；节气日期放在 assets/mock/solar_terms.json；有农事的日期按类型显示彩色圆点。
•  H04：保存时写入 farm_task 并调用 FarmTaskReminderWorker.schedule；「AI 提示」由 FarmIndexCalculator 根据逐小时预报给出最佳作业时段，不调用大模型。
•  H05：PointsRepository.checkIn() 保证一天只能签到一次，计算连续天数；连续第 7 天得 10 + 20 = 30 积分、5 + 10 = 15 成长值；每日任务完成状态来自当天的 points_txn；徽章进度按记录数量计算。
12.3 作物（C01–C05）
•  C01：筛选 Chip（全部 / 大棚 / 露天 / 需关注）用 BehaviorProcessor 保存当前筛选，switchMap 切换查询；生长进度 = 已种天数 ÷ 预计天数。
•  C02：CropWithRecords（@Relation）一次取出作物和农事记录；生长阶段步进条按已种天数和作物生长期表计算；Tab 切换农事记录 / 生长数据 / 照片。
•  C03：新增与编辑共用；预计采收日期 = 定植日期 + 作物默认生长期（作物生长期表放在 assets/mock/crop_profiles.json）。
•  C04：表单字段随记录类型变化（施肥 → 肥料名称 / 用量，用药 → 药剂名称，灌溉 → 方式）；「同步到收支记账」开启时在同一事务内写入 ledger_entry；现场照片用 PickMultipleVisualMedia 选择（最多 9 张），复制到 App 私有目录。
•  C05：总面积 = SUM(地块面积)，利用率 = SUM(作物面积) ÷ SUM(地块面积)；本季投入 = 该地块作物的支出合计。

•  D06：见 9.3–9.4；用户在对话中附带图片时，改用识图模型（非流式）回答这条消息，提示词不要求 JSON；会话列表和清空功能与 M11 共用 chat_session 表。
•  D07–D09：集市分页见 7.6，置顶商品（pinned_until > 当前时间）排在最前；商品图片轮播用 RecyclerView + PagerSnapHelper；发布时开启「置顶 24 小时」在同一事务内扣除 100 积分并写入 pinned_until，积分不足时开关不可用。
•  D10：按月统计用 SUM(amount_cent) … GROUP BY；近 6 个月结余柱状图和支出构成图用自定义 View（Canvas）绘制；来自农事记录的条目标注来源。
•  D11：自定义数字键盘（GridLayout）维护金额字符串，限制两位小数；支出 8 类、收入 4 类，切换收支时重置类别。
12.5 农友圈（S01–S09）
•  S01：推荐 / 关注 / 问答 / 同城四个 Tab 对应不同查询；点赞、关注采用乐观更新：先改本地状态，失败回滚并提示；点击用 throttleFirst(800ms) 防止连点。
•  S02：发送评论后插入 comment 并更新评论数，新评论显示在列表顶部「老李种菜（我）· 刚刚」；作者回复带「作者」标识。
•  S03：动态 / 提问两种模式各自保存草稿（draft 表）；提问模式可设置悬赏积分（10–100），发布时扣除；7 天无人回答，App 启动时检查并退回积分。
•  S04 / S05：只有提问者能看到「采纳」；采纳在同一事务内更新回答 accepted、问题 status = SOLVED，回答者获得悬赏积分和 20 成长值（回答者是当前用户时写入 points_txn），其余「采纳」按钮隐藏。
•  S06 / S07：关注关系四种状态（关注 / 已关注 / 回关 / 互相关注）由双方关注标记计算。
•  S08：评论回复、赞和收藏、新增关注、系统通知来自 notification 表；「全部已读」批量更新。
•  S09：MockReplyEngine 根据 replies.json 的关键词选择回复，Single.timer(1500ms) 后插入对方消息，模拟真实聊天；顶部显示关联的集市商品卡片和防诈骗提示。
