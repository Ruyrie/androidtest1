# 与设计文档的差异与决策记录

设计文档（`docs/spec/`）和原型（`docs/prototype-src/`、`pic` 分支）在开发过程中**没有修改**。本文件记录开发中与它们不一致的地方，以及文档没写明、开发时做出的选择。**后续开发以本文件为准**：

- 「A. 用户决定」一节的条目是用户本人明确拍板的，必须遵守。
- 「B. 实现中的取舍」一节是各模块实现时按「最贴近原型、最保守」原则做的选择，可以按需调整，但调整前请先确认。

## A. 用户决定（必须遵守）

### A1. 技术与服务

| 项 | 决定 |
|---|---|
| minSdk | 31 |
| 包名 | `com.heban.app` |
| AI 问答 | DeepSeek（OpenAI 兼容 `/chat/completions`，SSE 流式），默认模型 `deepseek-v4-flash` |

### A2. 产品规则

1. **「再按一次返回退出应用」**：设计文档没有，用户要求新增。返回栈到底时，2 秒内第二次按返回才退出，第一次弹 Toast「再按一次返回键退出禾伴」（`ui/MainActivity` + `ui/common/BackPressExitHelper`）。
2. **新账号不导入示例数据**：技术准备文档 7.5 的 `sample_farm.json`（新账号可选的示例地块 / 作物 / 农事）**不使用**。个人数据全部从空开始，各列表显示空状态。
3. **共享模拟内容照常导入**：病虫害百科、集市商品、农友、动态、问答、积分商品等「将来由后端提供」的内容，所有账号共享导入。
4. **数据按账号隔离**：每个账号只看到自己的作物、农事、记账、积分、关注、订单等（表中 `user_id`）。
5. **游客只能浏览**：所有写操作先弹「登录后才能使用」对话框（`LoginRequired`），按钮「去登录」。
6. **缺 Key 只显示错误提示**，不显示示例数据（天气、AI）。
7. **棚内温湿度手动记录**：C05 大棚地块可手动记录温度 / 湿度；湿度 ≥ 85% 显示「湿度偏高」。
8. **作物「需关注」**两个来源：
   - 拍照识别结果保存到作物（来源 scan）；
   - 天气自动判断（来源 weather），例如黄瓜 + 湿度 ≥ 85% →「霜霉病风险」。
   - 用户可手动取消；取消后 3 天内天气规则不再自动标记；天气规则不覆盖识别结果的标记。
9. **病虫害百科约 30 条**：实际 31 条。原型里的「128 种 / 共 128 条」是示例数字，页面显示真实条数。
10. **A04 验证码登录的协议勾选框默认不勾选**（合规要求）。
11. **M07 修改密码**的规则文案改为「**不能与最近使用过的密码相同**」（原型是「不能与最近使用过的 3 个密码相同」）。
12. **D02 拍照识别页底部文案**改为「**照片将发送到云端大模型识别，结果仅供参考**」（原型「识别在本机完成，结果仅供参考」与实际不符）。
13. **图片**：示例图片（技术准备文档 7.5、附录 B 的维基百科图片）暂不下载，全部显示占位图；以后补图放入 `app/src/main/assets/images/{crops,pests,products,mall,posts}/` 并附 `CREDITS.md`（文件名见附录 B 和各 JSON 里的路径）。
14. **只写代码，不改设计文档和原型**（差异记录在本文件）。

## B. 实现中的取舍（按模块）

### B1. 全局 / 主题

- 全局关闭中文额外行距（`fallbackLineSpacing=false`），以贴合原型行高。
- 协议文字（`view_agreement.xml`）用 BodyMedium（14sp），链接为中等字重。
- 筛选 Chip 共用配色 `@color/chip_filter_stroke` / `chip_filter_text`。
- 头像：UI 设计文档规定「无头像时用昵称首字」，所以「老李种菜」显示「老」（原型画的是「李」）。
- 模拟农友头像底色按 id 固定（`AvatarColors`），与原型一致。

### B2. 账号（A01–A09）

- A06 完善资料选的头像**没有持久化**（当时没有资料接口；现在 `UserRepository.updateProfile` 已定义，实现后可补上）。
- remote 版本额外用了两个后端接口：`auth/sms-code/verify`、`auth/registered`（后端未上线）。
- 表单按钮在输入合法前保持禁用。
- 密码强度：同时含大小写字母也算「强」的条件之一（`PasswordStrength`）。

### B3. 作物数据层（M2）

- 生长期表 `crop_profiles.json` 共 20 种作物。原型中的数字可以复现，例如番茄 110 天、第 68 天为结果期、进度 61%。
- C02 步骤条显示阶段名（育苗 / 定植 / 开花 / 结果 / 采收），卡片上加「期」（结果期）。
- 「预计还需 N 天」= 生长期 − 已种天数，这样与原型的 42 一致；若按日历日期算会是 43。
- 品种优先匹配，例如「番茄 · 樱桃番茄」用樱桃番茄的表。
- 未知作物用默认值：90 天，图标 eco，阶段为定植 / 生长 / 成熟。
- 自定义预计天数时，各阶段按比例缩放。改名且天数仍是旧默认值时，换成新作物的默认值。
- 编辑时保留的字段：
  - 作物：需关注信息、创建时间；
  - 任务：完成状态、系列 id；
  - 地块：最近一次温湿度读数；
  - 农事记录编辑：会先删除原来同步的支出，再按需重新写入。
- 静默不报错的情况：天气规则遇到未登录或作物不存在；删除他人或不存在的数据。
- 农事提醒 Worker：只在提醒时间仍在未来时安排；任务不属于当前登录账号时不弹通知。
- C05：利用率封顶 100%（原型的 88% 用它自己的示例数据算不出来）；总面积保留 2 位小数；「本季投入」= 该地块当前作物的全部支出，不按季节截断。
- 重复任务最多生成 366 条。
- 删除账目时，会清除对应农事记录上的账目关联。
- 原型没有出现的作物，图标为自选：辣椒 local_fire_department、叶菜 spa、根茎类 potted_plant。
- 已种天数在数据发射时计算，页面跨午夜不自动刷新。

### B4. 天气（M3）

- 只实现了「降温预警」一种预警（文档只定义了这一种）。
- 霜冻指数按表 8-3「最低温 ≤ 2°C」：原型示例数据最低 7°C，所以显示「无风险」，不是原型的「12日起注意」（另有测试用霜冻数据）。
- 喷药时段只在 6:00–19:00 内找；夜间改看次日上午，文字前加「明天 」。
- 当前小时用实况数据补齐，因为和风逐小时预报从下一小时开始。这样 15:02 时得到「15:00–18:00」。
- 降温持续期规则（各日最低温与首个降温日相差 1°C 内即连续）是自定，用来复现原型的「12–14 日」。
- 阈值：
  - 喷药：「适宜」= 降水概率 < 30%、风 ≤ 3 级、10–30°C；「较适宜」= 风 ≤ 4 级、降水概率 ≤ 60%。
  - 灌溉：24 小时降水 ≥ 5mm 时为「暂不需要」。
  - 施肥：24 小时降水 ≥ 10mm，或任一小时 ≥ 2.6mm 时为「不宜」。
  - 晾晒：按当天预报判断。
  - 通风：湿度 ≥ 85% 时为「上午为宜」。
  - 降温预警：未来 3 天最低温比今天低 ≥ 8°C，或最低温 ≤ 8°C 且比今天低 ≥ 5°C。
  - 需关注：露天作物 3 天内最低温 ≤ 2°C 为「霜冻风险」（优先）；黄瓜湿度 ≥ 85% 为「霜霉病风险」；番茄湿度 ≥ 85% 为「灰霉病风险」；大棚作物优先用 24 小时内手动记录的棚内湿度。
- 缓存 30 分钟；自动加载失败后 1 分钟内不再自动重试。下拉刷新不受限制。
- 自拟文案（文档没有）：
  - 未配置提示「未配置天气服务，请在 local.properties 中填写和风天气的 API Host 和 Key」；
  - 各 HTTP 错误提示；
  - 「请选择地点」；
  - 「夜间排湿 / 视墒情 / 暂无数据」等等级；
  - H04 中除喷药外的其他类型提示。
- 「多云转晴」：逐日预报增加夜间天气，首页 / 天气页显示「白天转夜间」；没有当天预报时用实况文字。
- 自动定位或资料地区解析出的地点**不保存**，只有在 H02 手动选择的地点才保存。
- 和风 v7 城市天气接口官方标注「即将弃用」，按文档仍用 v7。遇到停用错误时提示「天气接口已停用，请更新 App」。
- 预警通知按「同一天同一条只通知一次」去重（DataStore 键 `weather.last_alert`）。
