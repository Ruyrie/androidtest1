### 3. 行为要求

**通用**
- 当前用户取自 `CurrentUser`。未登录时，个人数据为空；写操作抛 `BusinessException("NOT_LOGGED_IN")`。
- 共享内容（农友、动态、问答）游客也能浏览。

**动态流** `feed(tab)`：返回 `PagingData<PostCard>`，可用 Room PagingSource + map。
- 推荐：全部可见的 POST，按 created_at 倒序。
- 关注：关注的农友的动态 + 自己的动态。
- 同城：city 与用户地区匹配。用户 region 形如「江苏省 南京市 江宁区」，匹配 南京 / 江宁。游客返回空，由界面说明原因。
- 自己的动态按 visibility 过滤：「仅自己」只对自己可见。

**问答** `questions(filter)`：使用 `CommunityRepository.Q_*` 常量。
- 与我作物相关：crop_name 在当前用户的作物名中。直接用 `db.cropDao()` 查询当前用户的作物。
- 我的提问：自己发布的问题。

**作者信息**：PostCard / CommentItem / FarmerCard 的作者来自农友或当前用户。
- 字段：昵称、avatar_text（取昵称首字）。
- 当前用户的徽标：用 `PointsRules.level(growth)` 和 `levelTitle` 计算。
- 点赞 / 收藏 / 关注标记分别来自 like / favorite / follow 表；images 的 JSON 要解析出来。

**切换操作**：`toggleLike`、`toggleCommentLike`、`toggleFavorite`、`toggleFollow` 在**同一个事务**里同时更新标记和显示的计数（likes / favorites / fansCount）。
- 关注某些农友（例如 1 草莓姐姐、2 王农艺师）后，对方会在短暂延迟后回关：插入 `FanEntity`，再发一条 FOLLOW 通知。
- 实现要简单、结果确定（每次都一样）。

**评论与回答**
- `comment()`：插入评论，同时把帖子的 comments 加 1。新评论在界面上显示为「老李种菜（我）· 刚刚」（取当前用户昵称）。
- `answer()`：插入回答，再调用 `points.award(PointsRules.TYPE_ANSWER, …)`。达到每日上限由 `LocalPointsRepository` 处理；积分失败时忽略，不影响回答本身。

**发布** `publish(post, aiAnswer)`：
- 设置 user_id、created_at、city；问题的 status 设为 OPEN。
- 悬赏问题：在 `db.runInTransaction` 里调用 `points.spendInTransaction(uid, PointsRules.TYPE_REWARD_QUESTION, "悬赏提问「…」", reward, postId)`。余额不足时抛出 BusinessException，整个发布回滚。
- 动态（POST）：发布后调用 `points.award(PointsRules.TYPE_POST, …)`。
- `aiAnswer = true`：调用 `ai.quickAnswer(question)`，成功后写入 ai_answer；失败忽略。
- 模拟功能：为了让用户自己的提问「活起来」，延迟 5–10 秒后插入 1–2 条农友的模拟回答，并发一条通知「你的提问「…」有 N 个新回答」。代码里要注明这是模拟。

**采纳与退回**
- `accept()`：只有提问者可以采纳。在一个事务里：
  - 回答的 accepted 设为 true；
  - 问题 status 设为 SOLVED，并写入 acceptedId；
  - 如果回答者是当前用户（mock 中不会出现），发放悬赏积分和 20 成长值；
  - 插入一条 SYSTEM 通知。
- `refundExpiredRewards()`：处理自己 OPEN 状态、reward > 0、超过 7 天（`PointsRules.REWARD_REFUND_DAYS`）且没有回答的问题：
  - 用 `TYPE_REWARD_REFUND` 退回一次；
  - 退回后把 reward 置 0，防止重复退回。
  - 由 T10 在启动时调用。

**其他**
- 草稿 `getDraft` / `saveDraft` / `deleteDraft`：按 type（POST / QUESTION）各存一份。
- `topics()`：固定列表，如 #番茄、#黄瓜、#草莓种植、#大棚管理、#果树管理、#病虫害、#农机、#收获 …
- `myStats()`：返回 `int[]{自己的动态数, 关注数, 粉丝数, 自己动态获赞数}`。
- `favorites()`：返回自己收藏的帖子（favorite 表中 TYPE_POST 的记录）。

**消息**（LocalMessageRepository）
- 会话按用户隔离。
  - `openConversation(farmerId, productId)`：找到已有会话或新建（KIND_FARMER）。
  - `openServiceConversation()`：KIND_SERVICE，第一条消息是 P09 开场白。
- `send()` 的流程：
  1. 插入我的消息，更新会话的 last_message / last_at；
  2. typing 设为 true（每个会话一个 `BehaviorProcessor`，由 `observeTyping` 暴露）；
  3. 农友会话：1500 ms 后由 MockReplyEngine 回复；客服会话：1000 ms 后按 FAQ 回复，没匹配到时回复「你的问题已记录，人工服务开放后会第一时间回复你。」；
  4. typing 设为 false。
- 计时用 `Single.timer`，便于测试时替换调度器。
- 未读：
  - 对方的消息使 unread +1；
  - `markConversationRead` 清零该会话；
  - `markAllRead` 清零全部会话和全部通知。
- `observeCounts()`：按 NotificationEntity 类型统计未读数，加上私信未读总数。
- `serviceQuickQuestions()`：返回 service_faq.json 的 `[问题, 答案]` 列表。
- `addNotification`：按用户写入。
