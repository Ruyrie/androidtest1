# 页面任务通用要求（T3–T9 都适用）

每个页面任务开始前先读本文件，再读对应的任务说明。

## 1. 实现一个页面的步骤

1. **对照原型**
   - 打开原型 PNG（`pic` 分支 `prototypes/<编号>_<名称>.png`）和 HTML 源（`docs/prototype-src/<名称>.dc.html`）。
   - HTML 里能直接读出：px 尺寸（即 dp）、颜色、文字、图标名（`<span class="ms">名称</span>`）、状态切换（`<sc-if>` / `renderVals()`）和示例数据。
   - 再读 UI 设计文档（`docs/spec/禾伴UI设计文档.txt`）中该页面的说明，以及技术准备文档第 12 章对应的小节。
2. **改写占位类**
   - 把占位类（`extends PlaceholderFragment`）改为 `extends BaseFragment`。
   - 新建布局 `fragment_<snake_name>.xml`（根节点 `<layout>`，变量 `vm`）和 `XxxViewModel extends BaseViewModel`（构造函数 `(AppContainer c)`）。
   - 写法见 `03-架构与开发约定.md` 第 2 节。
3. **颜色、字体、间距、图标**
   - 颜色只用主题属性，不写死色值，对照表见 03 第 6 节；字体用 `?attr/textAppearanceXxx`；间距用 `res/values/dimens.xml`。
   - 图标用已有的 `@drawable/ic_<名称>`（线框）或 `ic_<名称>_fill`（实心）。原型里出现的 Material Symbol 都已生成，缺的再按同样格式补。
4. **资源命名与字符串**
   - 资源加页面前缀，字符串放在任务指定的 `strings_<模块>.xml`。
   - 原型里出现的文字必须**逐字一致**。
5. **登录与空状态**
   - 写操作前先调用 `if (!LoginRequired.check(this)) return;`。
   - 每个列表都要有空状态（图标 + 一句说明 + 可选按钮）：新账号的个人数据是空的。
   - 游客状态也要能正常显示。
6. **共用头像与徽标**
   - 头像：`AvatarColors.apply(textView, farmerId, me)`，背景 `@drawable/bg_avatar_circle`。
   - 徽标：`BadgeStyles.apply(textView, badge)`，背景 `@drawable/bg_badge`。
7. **图片**
   - 一律用 Glide 或 Picasso 加载，并设置占位图：作物用作物图标，其他用 `@drawable/ph_image`。
   - 图片文件不存在时不能崩溃。
8. **导航**
   - 按目的地 id 导航，参数键用 `ui/common/NavArgs`。
   - 不要为了一个页面新增 action；需要改 `nav_graph.xml` 时只改对应的目的地。

## 2. 验证

1. 构建两个 flavor，跑全部单元测试（命令见 01 第 3 节）。
2. ViewModel 测试（纯 JVM，用假仓库）覆盖任务说明里列出的规则。
3. 本地截图（01 第 5 节）与原型 PNG 逐项对比：
   - 位置、文字、字号、间距、颜色、图标；
   - 有深色原型的页面再比深色模式；
   - 空状态和游客状态也截一张。
   - 截图用的假数据取原型里的示例值，便于对比。
4. 与原型或文档不同的地方，写进 `04-与设计文档的差异与决策记录.md`。
5. 页面完成后，把 `02-页面进度清单.md` 中该页的状态改为 ✅。
6. 按 01 第 4 节的规则提交并推送。

## 3. 原型中「功能暂未开放」类入口

原型或文档明确写了「暂未开放」的入口，点击后显示 Snackbar「功能暂未开放」（`R.string.feature_not_open`），例如帮助与反馈、检查更新、实名认证。其他原型没有画出后续页面的入口，也照此处理，并记入 04。
