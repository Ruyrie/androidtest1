## 要做的

### 1. 账号（mock + remote）

**`updateProfile(profile)`**：把可编辑字段合并进已保存的用户，其他字段不动。可编辑字段：
- nickname、bio、region、years、identity、skills；
- avatarPath、coverPath；
- showCrops、showBadges。

校验规则：
- 昵称距上次修改不足 30 天时抛出 `Errors.NICKNAME_LOCKED`，提示「昵称 30 天内只能修改 1 次」。修改成功后写入 nicknameChangedAt。
- 简介最多 60 字；擅长作物最多 5 个。

**`changePhone(newPhone)`**：
- 与原手机号相同时抛 `SAME_PHONE`；
- 手机号已被占用时抛 `PHONE_EXISTS`（mock 在 Room 中检查唯一性；remote 调用 `PUT /auth/phone`）。

**`deleteAccount()`**：写入 deletedAt，然后执行 logout。

**remote**：在 `HeBanApi` 中增加 `PUT users/me`、`PUT auth/phone` 和注销接口（后端未上线，接口按 8.4 约定）。

### 3. LocalMallRepository

所有数据按 `CurrentUser` 隔离。

- `observeItems(type)`：type 为 全部 / 实物 / 装扮。
- `observeRedeemedQty(itemId)`：当前用户已兑换的数量。

**`redeem(itemId, qty, addressId)`**：

先校验，失败时抛 BusinessException，消息如下：

| 情况 | 消息 |
|---|---|
| qty > limitPerUser − 已兑换 | 「超出每人限兑数量」 |
| stock < qty | 「库存不足」 |
| 余额 < price × qty | 「积分不足」 |
| 实物没有地址 | 「请选择收货地址」 |

校验通过后，在**一个** `db.runInTransaction` 里依次执行：
1. `points.spendInTransaction(uid, PointsRules.TYPE_REDEEM, "兑换「商品名」", price×qty, orderNo)`；
2. 插入订单：
   - orderNo 为 `DH` + `yyyyMMddHHmm`，与原型 `DH202610100917` 的格式一致；同一分钟内重复时自行加后缀，并记入 04；
   - 实物生成 `HB` + 12 位数字的 trackingNo；
   - 地址以 JSON 快照保存在 addressJson；
3. 库存 − qty，sold + qty；
4. 装扮商品直接把状态设为「已发放」。

最后返回订单。

**物流**（全部确定性计算，不随机）：
- 从 createdAt 推出时间线：待发货（0）→ 已揽收（约 +1 天）→ 运输中（约 +1.2 天，2 个中转节点）→ 派送中（约 +2.5 天）→ 已签收（约 +3 天）。
- `logistics(order, now)`：只返回已到达的节点，最新的在前。文字仿照原型：发货仓「禾伴官方仓（苏州）」，中转「苏州分拨中心」「南京江宁转运中心」；能取到订单地址的城市时，换成该城市。
- `statusAt(order, now)`：给定时刻的状态。
- `estimatedAt(order)`：预计送达或预计发货时间。

**订单与地址**：
- `observeOrders(tab)` 用 `TAB_*` 常量：
  - wait = 待发货；
  - ship = 已揽收 / 运输中 / 派送中；
  - done = 已签收 / 已发放。
  - 状态按当前时间计算。
- `changeOrderAddress`：只允许在「待发货」状态修改。
- 地址规则：
  - 最多 10 个，超出时提示「最多保存 10 个地址」；
  - 第一个地址自动设为默认；默认地址唯一；
  - 手机号必须匹配 `1\d{10}`；
  - 删除默认地址后，把最早添加的地址设为默认。

### 4. LogisticsWorker（新建 `worker/LogisticsWorker.java`）

- 使用 PeriodicWorkRequest，每 2 小时一次，需要联网。
- 提供 `ensureScheduled(Context)`：
  - 有未签收的实物订单时 enqueue（唯一任务，KEEP）；
  - 没有时 cancel。
- 执行时：用 `statusAt` 计算每个订单的当前状态，与保存的状态比较；有变化时更新订单，并在 `order` 渠道发通知（例如「你兑换的 番茄种子组合 已到达南京江宁转运中心」）。
- 通知的权限检查方式参照 `util/Notifier`，也可以在 `Notifier` 中增加 `showOrderUpdate(...)` 方法。
- 通知点击打开 P08，传入 `NavArgs.ORDER_NO`。
- 启动时调用 `ensureScheduled` 的工作放在 T10。

### 5. DataExporter（新建 `data/export/DataExporter.java`）

- 方法签名：`public static Single<String> export(Context ctx, AppContainer c)`，返回保存的文件名。
- 导出当前用户的作物、农事记录、收支记账三类数据：
  - 编码为 **UTF-8 BOM** 的 CSV，Excel 可以直接打开；
  - 字段含逗号、引号或换行时，按 CSV 规则转义。
- 通过 `MediaStore.Downloads` 保存到「下载」目录，文件名形如「禾伴数据导出_yyyyMMdd_HHmm.csv」。可以三类合成一个文件（分节），也可以分成三个文件；选择记入 04。
- 未登录时抛出 NOT_LOGGED_IN。
