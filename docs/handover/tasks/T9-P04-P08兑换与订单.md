## 与文档的出入（实现时按这里做，并记入 04）

技术准备文档写「P05 选择地址后通过 mall_graph 共享的 ViewModel 带回」，但 `nav_graph.xml` 中 `addressFragment` **不在** `mall_graph` 内（P07 修改地址也要用它）。

做法：
1. P05 进入 P06 时传 `NavArgs.PICK_ADDRESS = true`。
2. P06 选中地址后执行 `nav().getPreviousBackStackEntry().getSavedStateHandle().set("picked_address_id", id)`，再返回。
3. P05 / P07 在自己的 `getCurrentBackStackEntry().getSavedStateHandle()` 上监听这个值。

P04 / P05 之间共享的 `MallViewModel` 用 `nav().getBackStackEntry(R.id.mall_graph)` 作为作用域。

## 数据接口

- `c.mallRepository`：
  - `observeItem`、`observeRedeemedQty`、`redeem(itemId, qty, addressId)`；
  - `observeOrders(TAB_ALL / TAB_WAIT / TAB_SHIP / TAB_DONE)`、`observeOrder(orderNo)`；
  - `logistics(order, now)`、`statusAt`、`estimatedAt`、`changeOrderAddress`；
  - `observeAddresses`、`saveAddress`、`deleteAddress`、`setDefaultAddress`。
- `c.pointsRepository.observeBalance()`。
- `util/PhoneMask`。
- 所在地区：做法同 T6 的 M03，用输入框 + 定位按钮（`RegisterRegionLocator`）。
- 实体：
  - `MallItemEntity`：类型为 实物 / 装扮；
  - `MallOrderEntity`：状态常量为 `STATUS_WAIT` 待发货 / `STATUS_PICKED` 已揽收 / `STATUS_SHIPPING` 运输中 / `STATUS_DELIVERING` 派送中 / `STATUS_SIGNED` 已签收 / `STATUS_ISSUED` 已发放；
  - `AddressEntity`。
- 模型：`LogisticsNode`。

## 行为要求

### P04（参数 `NavArgs.MALL_ITEM_ID`）

**图片区**：图标放在着色方框中作为占位；有多张图时显示「1 / 3」页码。顶栏为返回、support_agent（进入 `serviceChatFragment`）。

**信息区**
- 「600 积分」、「已兑换 318 · 剩余 126 件」、商品名。
- 特性行：
  - verified：禾伴官方发货；
  - local_shipping：包邮 · 3 天内发货；
  - person：每人限兑 2 件。

**兑换数量**
- 步进器最小 1，最大为 min(限兑 − 已兑, 库存, 余额 ÷ 单价)。
- 下方显示「共需 1,200 积分 · 我有 1,280」。

**说明区**：「商品说明」「兑换须知」，内容按原型。

**底部栏**：「客服」+「立即兑换 · 600 积分」。
- 积分不足、售罄或已达限兑时按钮禁用，并显示原因。
- 点击需要登录，然后进入 P05，参数 `NavArgs.QTY`。

### P05

**地址卡**（装扮类商品不显示）
- location_on 图标、「老李 138****5678」+「默认」标签、完整地址、chevron。
- 点击进入 P06 选择模式。
- 没有地址时显示添加地址卡，文案原型没有，自拟并记入 04。

**商品行**：图标、商品名、「禾伴官方发货 · 包邮」、「600 积分 × 1」。

**汇总**：商品积分 / 运费（包邮）/ 当前积分 / 兑换后剩余；下面是提示说明。

**按钮**：「确认兑换 · 600 积分」，调用 `redeem`。

**成功态**（与原型一致）
- redeem 图标、「兑换成功」、「已扣除 600 积分，剩余 680」、「禾伴官方将在 3 个工作日内发货」、「订单号 DH…」。
- 「查看兑换记录」：进入 `ordersFragment`，popUpTo mall_graph inclusive。
- 「继续逛」：进入 `pointsMallFragment`，popUpTo mall_graph inclusive。

**失败**：Snackbar 显示 BusinessException 的文案（积分不足 / 超出每人限兑数量 / 库存不足 / 请选择收货地址）。

### P06（可选参数 `PICK_ADDRESS`）

**地址列表**
- 每行：单选、收货人、脱敏手机号、「默认」标签、地址、编辑图标。
- 说明文字「最多保存 10 个地址，点选即为本次兑换的收货地址」。

**新增收货地址**：表单可做成底部弹窗或页内表单，样式按原型。
- 字段：关闭 ×、收货人、手机号（+86）、所在地区、详细地址（带 my_location 图标）、「设为默认地址」开关。
- 「保存」启用条件：收货人非空、手机号匹配 `1\d{10}`、详细地址不少于 4 个字。

**编辑与删除**：编辑走同一个表单；删除先确认。

**选择模式**：点击地址后把结果带回并返回。

**登录**：需要登录。

### P07

**顶栏**：返回、「兑换记录」、support_agent。

**Tab**：全部 / 待发货 / 已发货 / 已完成，对应 `TAB_ALL / TAB_WAIT / TAB_SHIP / TAB_DONE`。

**订单卡**
- 「10月10日 · DH202610100917」。
- 状态文字颜色：待发货 warning，运输中 tertiary，已发放 / 已签收 primary。
- 图标、商品名、描述。描述示例：「× 1 · 预计 10月13日前发货」、「× 1 · 预计 10月11日送达」、「装扮 · 可在编辑资料中更换」。
- 「600 积分」。

**操作按钮**：每张卡都有「联系客服」，另按状态显示一个：

| 状态 | 按钮 | 去向 |
|---|---|---|
| 待发货 | 修改地址 | P06 选择模式，选好后调用 `changeOrderAddress` |
| 运输中 | 查看物流 | P08，参数 `ORDER_NO` |
| 装扮 | 去使用 | `editProfileFragment` |
| 已完成 | 再次兑换 | 回到对应商品 |

**空状态**（与原型一致）：inventory_2 图标、「暂无相关订单」、「去商城看看」。

### P08（参数 `NavArgs.ORDER_NO`）

**状态头**：local_shipping 图标、「运输中」、「预计 10月11日（明天）送达」。

**商品卡**
- 图标、商品名、「禾伴合作物流 · HB7531 0926 4418」。运单号每 4 位加一个空格。
- content_copy「复制」：写入剪贴板，提示「运单号已复制」。

**时间线**：竖向排列，最新的在上，当前节点高亮；数据来自 `logistics(order, now)`。

**底部**：地址卡；「联系禾伴客服」按钮进入 `serviceChatFragment`。

**通知入口**：T2 的 LogisticsWorker 发出的通知点开后进入本页。
