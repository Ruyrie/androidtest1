# 禾伴 · 项目文档

本目录存放禾伴 Android App 的设计依据和开发交接资料。所有内容以 `main` 分支的代码为准。

## 目录

| 路径 | 内容 |
|---|---|
| `spec/禾伴UI设计文档.docx`（`.txt` 为纯文本版） | UI 设计文档：设计规范、页面清单、交互和空状态规则 |
| `spec/禾伴技术准备文档.docx`（`.txt` 为纯文本版） | 技术准备文档：选型、包结构、数据表、接口、各模块实现要点、测试方案 |
| `spec/禾伴原型图.pdf` | 全部原型页合成的 PDF |
| `prototype-src/*.dc.html` | 原型 HTML 源文件，是精确尺寸、颜色、文字、图标名和示例数据的来源 |
| `pic` 分支 `prototypes/*.png` | 原型 PNG（824×1830，即 412×915dp 的 2 倍图），按页面编号命名，如 `S01_Community.png` |
| `tools/` | 本地验证工具，不属于工程本身：Robolectric 截图测试模板、Gradle init 脚本 |
| `handover/` | **开发交接文档（接手请从这里开始）** |

## 交接文档阅读顺序

1. `handover/01-交接总览.md`：项目概况、当前进度、环境与构建、`local.properties`、仓库规则、截图验证方法。
2. `handover/02-页面进度清单.md`：61 个页面逐页的状态（30 个已实现，31 个占位）。
3. `handover/03-架构与开发约定.md`：包结构、MVVM 写法、仓库实现状态、数据库、设置项、视觉规范、资源命名、模拟农友、测试、踩过的坑。
4. `handover/04-与设计文档的差异与决策记录.md`：用户决定的改动，以及实现中的取舍。**与设计文档冲突时，以本文件为准。**
5. `handover/05-后续工作清单.md`：剩余工作的顺序、集成待办、需要用户决定的事项、已知问题、最终验收清单。
6. `handover/tasks/`：每项剩余任务的详细说明。
   - `00-页面任务通用要求.md`：页面任务共用的步骤和验证要求。
   - `T1`–`T10`：每个任务列出原型、文档出处、接口、行为要求、已有调用方和验收标准。

## 对接手者（包括使用 AI 编程助手时）的要求

- 不要凭印象写：
  - 接口名、字段名、导航 id、设置键，一律先在代码里确认（文档中引用的都已逐一核对过）；
  - 页面的文字、尺寸、颜色，以 `prototype-src` 中的 HTML 为准；
  - 规则以两份设计文档和 `04` 为准。
- 文档和原型都没有写明的地方，不要自行假定。先列出问题请项目负责人确认；确认后再实现，并记入 `04`。
- 每完成一部分都要：构建两个 flavor，跑全部单元测试，用本地截图与原型对比，然后更新 `02` / `04`，再按 `01` 第 4 节的规则提交。
